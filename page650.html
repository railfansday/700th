To convey the complexity of this particular bug, we first need to explain how Hyperdrive works.

Hyperdrive is a distributed database connection pooler that connects Cloudflare Workers to SQL databases. Hyperdrive holds warm SQL connections open on our global network and shares these connections across many Worker requests. In addition to connection pooling, Hyperdrive can also cache common queries in our global CDN cache, reducing latency and load on the origin database.

Establishing a connection to a SQL database is expensive, taking a minimum of five network round trips. On a serverless computeÂ platform like Workers, establishing a connection for each request would be impractical, both because of the amount of latency added to each request, but also because a large number of open connections can incur high per-connection resource costs. While MySQL fares better here than Postgres since MySQL doesnât use an entire OS process per connection, a typical deployment can still run into resource issues with a large number of connections.

For more details, see our blog post introducing Hyperdrive.

Some of the issues we ran into were small and easy to fix once reported. One of the first problems reported in the beta was that emojis written to the database were not being correctly returned. This was a bug related to character set encoding. Hyperdrive negotiates the encoding for the connection in the startup handshake, and we negotiate utf8Â as the encoding. As it turns out, utf8Â is a deprecated aliasÂ for utf8mb3Â which is notÂ all of UTF-8: it only supports 1â3 bytes per Unicode code point, while full UTF-8 has a max of 4 bytes per code point. To get all of UTF-8, we needed to change our handshake to use utf8mb4Â , which fixed the emoji issue.

Another encoding-related bug occurred when we added connection cleanup via COM_RESET_CONNECTION. This is a lightweight MySQL command to clear any session state in a given connection, which is exactly what Hyperdrive needs to ensure that no session-level state leaks between checkouts. But adding this connection cleanup step caused encoding issues once again! It turns out that COM_RESET_CONNECTION does not reset the connection state to the character set encoding we negotiated at connection startup; it instead resets the connection to the server default. This means that after negotiating utf8mb4 on a MySQL server instance that defaults to latin1, once we run COM_RESET_CONNECTION, our connection now has an encoding of latin1. The fix is to always run a command setting the encoding to utf8mb4 after a connection reset.

Then we also increased the trace rate for this Hyperdrive instance, hoping to see the execution flow of this bug. We searched for network issues that could explain the issue â but nothing seemed to account for this behavior. This error occurred about 0.001% of the time, which made it very hard to find relevant end-to-end execution traces.

But we did have one clue: the bug only occurred on Hyperdrive instances with caching enabled. This made us suspect an issue with Hyperdriveâs MySQL caching.

To understand Hyperdrive's caching, we first need to talk about Hyperdrive's topology and how it interacts with the CDN cache. Every Hyperdrive instance has a split architecture with two nodes: a Client and an Endpoint. The Client node runs on the same machine as the userâs Worker, handles local caching (if enabled), andÂ forwards queries to the Endpoint if needed.Â The Endpoint node holds the connection pool and is placed in the data center closest to the origin database. Each node uses the Cloudflare CDN cache local to the data center it is running in. Importantly, this means that if the two nodes are running in the same data center, they will share a cache.

Sharing the cache between Client and Endpoint is generally good for performance. We use a hash of the contents of the queryâs wire messages with some normalization and store the result bytes in the cache. If a Hyperdrive Client running in the same data center as its Endpoint receives a request, and that Endpoint has recently cached the results of the same query, the Client can serve the response directly from the shared data center cache. To work correctly, this scheme requires that the same bytes are cached for the same response, whether stored by the Client or the Endpoint.

The protocol describes how a MySQL client communicates with a MySQL server. This can be somewhat confusing in the case of database connection pooling since we have two components acting like clients and two acting like servers. The first client is the Worker using a MySQL client library, and it connects to the first component acting like a server, the Hyperdrive Client. The Hyperdrive Client connects to the Hyperdrive Endpoint which acts as a MySQL client connecting to the actual MySQL origin server.

This protocol starts with the Connection PhaseÂ where the MySQL client and the MySQL server agree upon a common authentication method and capabilities. Once a connection is established, the client and server begin the Command Phase, where the client sends commands (e.g. SQL statements) to be executed with the server responding and waiting for the next command.

Capabilities are exchanged during the Connection Phase to support protocol evolution while remaining backwards compatible. Each capability is a feature, like supporting compression during the Command Phase. The clients and servers must only use features which the other supports, otherwise a protocol desync can occur, leading to unexpected behavior.

This capability negotiation can be tricky for Hyperdrive, since Hyperdrive acts as a client to the origin database, and acts as a server to the Worker. To ensure that Hyperdrive can parse the messages from the origin MySQL server, Hyperdrive has a fixed set of capability flags which are used to communicate to the origin database. Since it is possible for Hyperdriveâs set of capabilities to be different from the Worker clientâs set of capabilities, Hyperdrive needs to translate all origin responses encoded by its capabilities to the capabilities that the Worker expects.

While trying to debug this issue, we found that a popular MySQL client library for Node.js (mysql2) does not currently supportÂ the CLIENT_DEPRECATE_EOFÂ capability, which changes how result sets are terminated. Without this capability, the server sends an EOF packet between the column definitions and rows, then another EOF packet at the end of the result set. When CLIENT_DEPRECATE_EOF is negotiated, the metadata EOF packet is omitted and the final EOF packet is replaced with an OK packet. MySQL server 5.7.5 and later supports this capability, but the newer OK-packet behavior is only used when the client negotiates it.

While Hyperdrive doesÂ support the CLIENT_DEPRECATE_EOF capability, itâs possible that the Workerâs MySQL driver does not. To handle this, Hyperdrive adjusts its behavior to support the capabilities that the Worker client driver expects. This means rewriting result sets to include EOFs and to translate all OK packets to EOFs when required.Â

We finally came across the last missing piece: a faulty assumption in our Hyperdrive Client caching code. We baked in an assumption when implementing the Client caching for Postgres: that we can cache exactly the bytes we wrote back to the Worker. While this was a reasonable assumption to make with Postgresâ wire protocol, it no longer holds due to the mismatch in MySQL capabilities. If a Client node is caching exactly what it writes back to the Worker, these bytes are in a different format than what an Endpoint node would be expecting. Thatâs because the Endpoint node is always working with Hyperdriveâs capabilities, while the Client node writes back bytes that are translated to match the Workerâs capabilities.

#4590. The Legend of Zelda: Ocarina of Time (2026) Preview - A Beautiful Step Back In Time

📅 14 Oct 2026 | Category: other | Source

Platform:
Publisher: Nintendo
Developer: Nintendo
Release: November 5, 2026
Rating: Everyone 10+

For nearly 20 years, The Legend of Zelda: Ocarina of Time was my favorite game. While it was eventually supplanted by The Legend of Zelda: Breath of the Wild, Ocarina of Time remains a formative, treasured gaming experience that laid the foundation for the wider 3D action genre. However, I am the first to admit that while the original Nintendo 64 version – the only one available on Switch and Switch 2 – has aged better than most games of its era, much like its iconic hero, it doesn't take long to realize it's from a bygone era. 

For years, I wanted Nintendo to bring the 2011 3D remaster to Switch, but it's doing me one better: a full, from-the-ground-up remake with lush visuals, several quality-of-life improvements, and even voice-acted cutscenes.  We are just weeks away from the launch of The Legend of Zelda: Ocarina of Time on Nintendo Switch 2, and ahead of its November 5 release, I spent over an hour exploring Hyrule as both Young and Adult Link.

My time begins the moment I take control of Link after Navi wakes him up. Following a brief conversation with Navi and Saria, who also ran up to Link's treehouse, it's time to retrieve the Deku Shield and Kokiri Sword so Mido will let me past to see the Great Deku Tree. As increasingly endearing as Saria is thanks to her improved facial and body animations, as well as her more fleshed-out dialogue, Mido is just as increasingly obnoxious; I was definitely happy to make him eat his words after he mocked Link for previously being the only one without a fairy.

Running around Kokiri Forest is nearly enough to sell me on this remake. The visuals are absolutely stunning. The new jump button and ability to sprint out of a roll make it feel like an all-new game. The freely controlled camera adds to this feeling, even with some relatively basic level design. And while I never had a problem with how Young Link looks in this remake, I'm even more impressed and comforted by seeing him in action in the actual game. In fact, everything surrounding Link also looks great; Kokiri Forest is much more bustling than its previous forms, light fog dissipates as you run through it, and swinging your sword looks better than ever before. Though I love Breath of the Wild and Tears of the Kingdom's stylish anime-inspired art style, the sheer amount of detail present in each and every character, enemy, and environment accentuates the masterfully executed maximalist approach Nintendo took with this remake.

After finding 40 rupees to buy a Deku Shield, I crawl through the tunnel to the area where you get the Kokiri Sword. This time, however, there's added verticality as you dodge the rolling boulders to reach a ladder, which you climb and then jump across a gap to reach the chest that contains the blade. This is indicative of small changes dedicated fans will find scattered throughout; I didn't uncover anything monumentally different from the original game, but eagle-eyed viewers of last month's Nintendo Direct will notice that Lon Lon Ranch is now on level with the rest of Hyrule Field rather than up on a plateau, and that Kakariko Village is now slightly rearranged. Outside of some small upgrades to the diversity and placement of foliage, I didn't notice many more differences, but it's also been several years since I last fired up either the N64 or 3DS version of Ocarina of Time, so it's entirely likely they were subtle enough that I didn't notice. 

After entering the Great Deku Tree and completing the first part where you jump off the ledge and break through the spiderweb, I must jump to the next part of the demo. Still as Young Link, I watch as Saria gifts Link the Fairy Ocarina through a touching, fully voiced (outside of Link, obviously) cutscene. From there, I'm dumped into Hyrule Field. It doesn't feel nearly as impressively endless as it felt in 1998, but it is definitely way more beautiful. After a brief conversation with the owl, Kaepora Gaebora, I sprint across Hyrule Field, catching passing yet impressive glimpses of landmarks like Lon Lon Ranch and Death Mountain. One new addition is apparent as I navigate the menus: The Threads of Time. Here, a tapestry tells the story of the Hero of Time in real time; I can look back at what has already happened in Link's adventure, as well as see how much is still on the horizon. Additionally, if you get lost, the tapestry can give hints for where you're supposed to go.

After a brief exploration of Hyrule Castle Town, including a short tour of the Temple of Time, it's time to jump ahead to the final segment of my demo: the Forest Temple. This section lets me try out Adult Link, who is equipped with the hookshot, and later, the Fairy Bow. This was the one place where my memory felt fuzziest, as I struggled to speedrun the puzzles that I last played through more than a decade ago.

Fighting Wolfos, Stalfos, and Skulltulas is more straightforward than most modern third-person fights, which may be the one area that fell slightly short of my admittedly lofty expectations. Using the lock-on targeting allows Link to dodge and counterattack, but I didn't find a simple way to swap targets when you're fighting multiple enemies at once. Instead, I had to release the left trigger, move the camera, and squeeze the trigger again. I get that this is how it worked in the original game, but I would have liked switching to the next target without going through that. Maybe there is an easy way to accomplish that, but I didn't find it in my nearly 90 minutes fighting through Hyrule.

Regardless of that one reservation, there is no doubt in my mind that The Legend of Zelda: Ocarina of Time will consume my life when it comes out. And with October already halfway in the rearview, we really don't have long before a whole new generation gets to experience what could very well be Link's greatest adventure. This remake of The Legend of Zelda: Ocarina of Time comes to Switch 2 on November 5.
